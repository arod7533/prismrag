Learn what each score tells you

All measurements are listed automatically in the local app, with scores and explanations. No metric selection or evaluation setup is required.

Answer accuracy
For an exact bundled question, a local judge checks the answer against its curated reference. Unlabeled questions show not measured. This differs from faithfulness to retrieved context.

Precision@k
Fraction of retrieved sources that are labeled relevant. Higher is better; measures noise. Repeated chunks from one source count once.

Recall@k
Fraction of all labeled relevant sources retrieved. Higher is better; measures missing evidence.

MRR
Reciprocal rank of the first relevant source. 1 means the first source is relevant; 0 means none were found.

nDCG@k
Discounted gain divided by the ideal ranking for binary relevance. Rewards putting relevant sources early.

Answer token F1
Token overlap with the reference answer. Useful for regression checks, but penalizes valid paraphrases and does not prove factuality.

Faithfulness
Local LLM judge scores whether answer claims follow from retrieved context (0–1), with a reason. A fallible estimate, not ground truth.

Answer relevance
Local LLM judge scores how directly the answer addresses the question (0–1), with a reason. Does not measure factual accuracy.

Context relevance
Local LLM judge scores usefulness of the retrieved passages for the question (0–1), with a reason. Does not replace labeled recall.

Latency
Wall-clock seconds for retrieval plus answer generation. Excludes judge time and indexing. Lower is better; warm and cold runs differ.

The local application automatically measures a bundled 20-question retrieval benchmark and judges each actual chat answer. All metrics and explanations are listed without setup controls. No benchmark scores are claimed on this page.

Inspect segmentation, not just dots

The local app projects actual normalized embeddings with PCA. Six topic colors group related documents. Full-vector topic-neighbor and silhouette diagnostics complement the scatterplot; exact boundary bars and full chunk text show how passages were split.

Inspect both textual boundaries and embedding neighborhoods. PCA retains only part of the variance; topic labels are human-authored and can overlap. Check labeled recall and ranking metrics too. No synthetic embedding plot is presented as measured output here.

Built to learn

A company introduction and six suggested questions help you start. Measurements explains each score, the pipeline stage it diagnoses and experiments to try based on actual results. Documents and evaluations load automatically.

Honest about uncertainty

Model judges can be wrong. Token overlap misses valid paraphrases. Vector projections lose information. PrismRAG shows the limits alongside the scores.

Run it on your machine

Install Ollama and uv, clone the repository, then run these commands from the project folder. Start ollama serve in a separate terminal if Ollama is not already running.

ollama pull qwen3.5:9b
ollama pull nomic-embed-text
uv sync --locked --python 3.12
uv run python app.py

Open http://127.0.0.1:7860, wait for the included documents to load, and ask a question.

Hosting boundary: this GitHub Pages showcase is static. Live Python and Ollama inference run locally, or on a separately provisioned server. Document content is processed locally by default.
